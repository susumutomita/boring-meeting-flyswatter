# User Stories Assessment

## Assessment

User stories add value for this project because the core novelty is not a complex backend architecture but a user-facing meeting intervention. The reviewer needs to understand why the product exists, who receives value, and how the game mechanic supports the hackathon theme.

## Decision

User Stories stage is executed.

## Rationale

- The product has multiple user roles: meeting participant, meeting facilitator, hackathon reviewer, and privacy-conscious user.
- The creative risk is high enough that explicit stories help connect playful mechanics to meeting improvement.
- Acceptance criteria can be tied directly to observable UI behavior.

## Scope

Stories cover the current MVP only:

- Browser-only meeting start and monitoring.
- Silence and inactivity detection.
- One-time swatting intervention.
- Score and recap.
- Reason picker and productivity score.
- WebRTC room sharing.
- Browser notification and Document Picture-in-Picture.

Future roadmap items such as a Hono signaling server, camera presence detection, and meeting history are excluded.
